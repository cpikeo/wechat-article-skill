# eval：真实案例与回归语料

**契约只有一条（人读、加用例时执行，不再自动化）：每篇用例必须至少独家覆盖一条判断路径。**
新增一篇之前，先写清它能测到什么别人测不到的东西；写不出，就不要加。

判据不是「这篇写得好不好」，而是：**去掉它以后，哪条路径就没人测了。**

## 覆盖表（历史输出 + 人读复核）

| 用例 | 人格 | 字数 | 资产状态 | 独家覆盖 |
|---|---|---|---|---|
| `skills` | paper | ~1100 | 无图 · 无封面 | 原语 h3 / 有序 / 无序列表 / code / hr / table |
| `portrait` | letter | ~1050 | 真实图 + 待补图 + 封面 | 人格 letter · 真实+待补混排 |
| `visual` | frost | ~710 | 真实图（标注示意）+ 封面 | airy · deck 单独作首屏 · 高潮靠前 · 生成图「示意」 |
| `brief` | folio | ~1000 | 封面待补 · 无图 | 密度 dense · 封面待补 |
| `longread` | paper | ~2025 | 封面 · 无图 | 字数档 ≥2000 · 目录 |

五篇覆盖：三种密度 · 三个字数档 · 四种资产状态 · 全部 12 个原语 · 高潮 47%–100%。
ink / bone 人格的**渲染**由 `selftest.py ②` 六格样张全覆盖，eval 不再为「只测人格」单独留整篇；
合并历史：ink 的 code/hr/table 进 `skills`，excerpt 的 airy/deck/高潮靠前 进 `visual`，atelier 的真实素材路径由 `portrait` 承接。

## 什么时候合并或删除

- **零独家覆盖** → 删（`letter.md` 就是这样处理的：它的 letter 人格覆盖已被 `portrait` 承接，
  其余路径都由 brief / portrait / skills 覆盖）。
- **两篇只差人格** → 若该人格已由别处覆盖，合并为一篇。
- **想加一篇新人格** → 先确认它至少改了 2 个编辑语言轴（见 `decide.md`「新主题」），
  再加用例；否则跑一遍 `--specimen` 就够了，不需要新语料。

## 机器基准（回归 ②）

`scripts/selftest.py` 的 `BASELINE` 锁 5 篇语料的**判断落点**，不只是「退出码为 0」：
人格 / 正文图数 / 有无 Peak / 目录是否生效 / 首屏附加层数。
图丢了、目录没了、主题被换掉，退出码照样是 0——只有这份快照会报。
改稿不该动这张表；这张表动了，说明这套 Skill 对这批文章的判断变了，那必须是有意的。

## 判断基准（不进代码）

密度、节奏、强调多少、高潮位置、裁切好不好看，一律由 Gate 3 通读 390px 预览下结论，
不写阈值、不写自动修复。语料里 `longread` 的高潮在 92%（靠结尾），是有意保留的一种节奏，
不是待修的缺陷——改它之前先回答「改了读者多得到什么」。

## 负例不在这个目录

14 条护栏（图片无承接 / 封面缺失 / 分辨率过低 / bars 非法 / 首图超预算 / todo 占预算 /
首屏三层 / 图示与正文重复 / 封面复用正文图 / 证据图无说明 / 短文开目录 / density 非法值 / 数据分隔符 /
转场不少于章节数）
都在 `scripts/selftest.py` 里**现场合成**，不占用 eval 文件。负例要的是覆盖，不是可读性。
