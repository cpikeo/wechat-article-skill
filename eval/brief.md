> 按人头收费的年代正在结束，但用量定价并不是免费的午餐——它把风险从客户手里搬回了供应商的报表上。

## 三张报表说的是同一件事

过去十年，SaaS 的商业模式被一句话概括：把软件卖成座位。人越多，收入越高；组织扩张，ARR 自动增长。这套逻辑在裁员周期里第一次失灵——客户不再招人，席位自然见顶，于是同一批产品开始把价格挂到使用量上。

这不是审美选择，是收入结构的选择。席位制卖的是「可能用到」，用量制卖的是「真的用了」。前者靠组织扩张，后者靠业务流量。

| 维度 | 席位制 | 用量制 |
|---|---|---|
| 收入来源 | 组织规模 | 业务流量 |
| 客户风险 | 买多了浪费 | 用多少付多少 |
| 供应商风险 | 续费稳定 | 收入随客户业务波动 |

## 净留存率把差距放大了

真正决定一家 SaaS 值不值得投的，不是新增，是净留存。同样的产品，不同的定价结构，净留存会分成四个档次，而且差距会随规模放大——这是定价迁移最被低估的后果。

::: bars
125｜净留存 % · 头部厂商（同期群口径）
105｜净留存 % · 行业中位
92｜净留存 % · 席位制为主的腰部厂商
78｜净留存 % · 客户流失严重的长尾
:::

领先者的净留存远高于持平线，意味着即使一个新客户都不签，收入也在自己增长；而尾部的厂商，每一年都要先把上一年的失血补回来，才有资格谈增长。**定价结构决定了这条曲线是向上还是向下。**

::: note 口径
净留存（NDR）指同一批客户在一年后的收入相对签约时的比例，不含新客；不同机构对同期群与折扣的处理不同，跨来源比较前先对齐口径。
:::

## 迁移的三条真话

第一，用量定价让收入更真实，也更颠簸。客户的业务好，你的账面就好；客户的用量掉下去，你的收入立刻跟着掉，中间没有合同保护期。

第二，它把「开通即收入」变成了「用起来才算数」。所以产品必须做到有人真的每天打开它，否则定价改变了，收入并不会自动改变。

第三，它要求供应商自己先算清单位经济。用量定价把成本从固定变成可变，一旦毛利率没算准，卖得越多亏得越快。

::: data
60天｜签约到首次超额
2.4倍｜次年用量收入 / 席位收入
1个｜真正要盯的指标：单位经济
:::

## 迁移不是换一张价目表

把价目表从「每席位」改成「每千次调用」，只是换了个单位。真正的迁移要同时改四件事：计量口径、账单呈现、销售激励、以及内部的成本核算。

这四件事里最容易漏掉的是销售激励——只要销售的提成还挂在签约额上，用量定价就会在内部被架空。指标不改，行为不改；行为不改，报表不改。

::: peak
定价的迁移，从来不是换个单位，而是把「谁承担不确定性」这件事重新分配一次。
:::
