# 自动推送配置教程（从零到把文章自动建成微信草稿/发布）

本教程解决"文章排好版之后，怎么不用手动复制粘贴、直接推到微信"这个需求。**在动手之前请先看清楚业务边界，这条边界比想象中要细致一些**：

> - 微信官方提供了 `freepublish_submit`（发布草稿）接口，可以做到**真正的自动发布、拿到正式文章链接**，而且它的姊妹接口 `draft/add` 能接受任意合规 HTML——**这意味着排版引擎产出的自定义视觉风格文章，可以通过官方 API 直接自动发布**，不需要任何格式转换。
> - 但 `freepublish_submit` **只对企业主体已认证的账号开放**（个人认证/未认证账号调用会直接报错 `48001`）。账号不满足这个条件时，"把文章真正发布出去"这一步都要回到人工在后台点确认——这是微信官方对账号资质的限制，不是本 Skill 能力不够。
> - **即使只是"建草稿"这一步（`draft/add`），也可能不是所有账号都能直接用**——微信有一个独立于账号认证的"草稿箱/发布功能"灰度开关（`draft/switch`）；这个开关没开的时候是否会导致 `draft/add` 也报同样的 `48001`，2026-07 复核官方文档后发现证据并不确凿（详见 `wechat-official-api-guide.md` 第 0 节），只作为需要排查的可能性之一保留，不再当作确定结论使用。遇到报错先按 errcode 排查表逐项排除，不要预设是哪一道门槛没过，更不要一律归因于"账号没认证"。
> - 不管走到哪一步，做到的都是"把文章发布成一篇正式文章"，**都不等于"主动推送消息提醒所有粉丝来看"**——那是另一套受限更严格的群发消息机制，历史上多数账号类型已经不能自由调用，本 Skill 也不会尝试提供或暗示这种能力。

把这几条边界记在心里，下面的内容就是关于怎么把"建草稿"乃至"真发布"这几步做到自动化。

---

## 0. 两个层级，按需选择

| 层级 | 效果 | 需要什么 |
|------|------|---------|
| L0：手动粘贴（默认，永远可用） | 排版引擎出 HTML，人工复制粘贴到公众号编辑器 | 不需要任何配置 |
| 官方 API 直发（真正发布+拿链接） | **保留排版引擎的自定义视觉风格**，自动建草稿 + （企业认证账号）自动提交发布 + 自动拿到正式文章链接 | 微信 AppID/Secret（纯 Python 标准库实现，不需要任何第三方命令行工具）+ 建议先确认账号的「草稿箱灰度开关」状态（是否必须开启仍待验证，见本教程第 3 节第 0 小节）+ 要真发布还需**企业主体已认证账号**，见 [wechat-official-api-guide.md](wechat-official-api-guide.md) |

官方 API 直发有两道门槛：企业认证（门槛二）是确定的，止步于建草稿还是能真发布，取决于账号是否企业认证；灰度开关（门槛一）是否会单独卡住建草稿这一步目前未经证实，遇到 `48001` 时把两道门槛都当作排查方向，不要预设结论。

## 1. 准备工作：拿到微信 AppID 和 AppSecret

1. 打开微信开发者平台：`https://developers.weixin.qq.com/platform`，用你公众号管理员的微信扫码登录。
2. 选择要接入的公众号（多个公众号注意别选错）。
3. 进入"开发接口管理"，找到：
   - `开发者ID(AppID)` → 直接复制。
   - `开发者密码(AppSecret)` → 通常需要点"重置"、完成管理员验证后才能拿到新密钥。
4. **`AppSecret` 务必妥善保管**：不要发给别人，不要提交到 Git 仓库，点了"重置"旧密钥会立刻失效（重置前确认没有其它系统还在用旧密钥）。

> 不同类型的公众号（订阅号/服务号，个人/企业认证）在微信接口权限上有差异，具体你的账号能调用哪些接口，以微信开发者平台实际展示为准，本教程不替你判断账号类型的能力边界。

## 2. 配置微信接口 IP 白名单（多数上传/建草稿场景都需要）

如果调用建草稿/上传相关接口时遇到类似：

```text
ip xxx.xxx.xxx.xxx not in whitelist
```

说明要配 IP 白名单：

1. 在**实际运行脚本的那台机器上**（本地电脑 / 云服务器 / CI，视你的运行环境而定）执行：
   ```bash
   curl ifconfig.me
   ```
2. 回到微信开发者平台 → 你的公众号 → "开发接口管理" → 找到"IP白名单" → 点"设置/修改"。
3. 把上一步查到的公网 IP 填进去（有多个固定出口 IP 就都加上）。
4. 保存后**等 1~5 分钟**再重试，白名单不是瞬间生效。

最常踩的坑：**在本地电脑查的 IP，结果程序实际跑在云服务器上**——白名单要加的是"真正发请求的那台机器"的公网 IP，不是你自己电脑的 IP。

## 3. 官方 API 直发（保留排版引擎视觉风格 + 真正自动发布）

用本技能包内置的 `assets/automation/wechat_official_publish.py`，直接调微信官方接口，纯 Python 标准库实现，不需要装任何第三方命令行工具：

### 3.0 先查一次开关状态（第一次用必做）

```bash
python3 assets/automation/wechat_official_publish.py \
  --appid "你的AppID" --secret "你的AppSecret" --check-draft-switch
```

返回 `is_open: false`，说明这个账号的"草稿箱/发布"新接口还没被灰度覆盖；接下来的 `draft/add` 是否会因此报 `48001` 目前证据并不确凿（见 `wechat-official-api-guide.md` 第 0 节 2026-07 复核提醒），先当作排查方向之一。确认要开启（**不可逆**，会把公众号后台"图文素材库"永久升级成"草稿箱"）就在后续命令里加 `--enable-draft-switch`；如果 `48001` 另有原因，开这个开关也不会解决问题，建议先按第 4 节逐项排查，别急着执行这个不可逆操作。

```bash
# 只建草稿（开关已开的前提下，任何认证状态的账号都能用这一步）
python3 assets/automation/wechat_official_publish.py \
  --appid "你的AppID" --secret "你的AppSecret" \
  --html "文章_排版_静纸(silent-paper).html" --cover "cover.jpg" \
  --title "文章标题" --author "作者名" --digest "一句话摘要"

# 建草稿 + 自动提交发布 + 轮询到成功/失败为止（仅企业主体已认证账号能走通"提交发布"这一步）
python3 assets/automation/wechat_official_publish.py \
  --appid "你的AppID" --secret "你的AppSecret" \
  --html "文章_排版_静纸(silent-paper).html" --cover "cover.jpg" \
  --title "文章标题" --author "作者名" --digest "一句话摘要" --submit
```

脚本会自动处理正文本地图片上传、封面走永久素材接口、`access_token` 用官方推荐的稳定版获取方式、发布状态异步轮询。**`--submit` 这一步只对企业主体已认证账号（服务号，或认证过的订阅号）有效**，个人认证/未认证账号调用会收到官方 `48001 api unauthorized` 报错，此时脚本已经把草稿建好了，只是"提交发布"这一步做不了，需要去后台手动点。如果连**建草稿**这一步就报 `48001`，先按第 4 节的排查表逐项检查（access_token 有效性、参数长度、IP 白名单等），开关状态只是其中一个待验证的可能性，不要预设就是开关的问题。

完整原理、两道门槛的详细拆解、账号资质判断方法、发布状态码含义，见 [references/wechat-official-api-guide.md](wechat-official-api-guide.md)，这是理解这条路径边界的关键文档，务必看一遍再上生产使用。

## 4. 常见错误速查

| 报错/现象 | 先查什么 |
|-----------|---------|
| `ip xxx.xxx.xxx.xxx not in whitelist` | 第 2 节：白名单里的 IP 是不是"实际运行机器"的公网 IP，而不是你本地电脑的 IP |
| `errcode=45004` | 先查 `--digest`/`--author`/`--title` 是否超出微信长度限制（摘要 128 字/作者 16 字/标题 32 字），不要一上来就归因于正文过长 |
| 建草稿卡在"缺少封面" | `--cover` 传本地图片路径；不要假设一个普通的图片 URL（包括 `mmbiz.qpic.cn` 链接）能直接当 `thumb_media_id` 复用 |
| 建草稿（`draft/add`）报 `48001 api unauthorized` | 先用 `--check-draft-switch` 查开关状态并检查 access_token/参数是否正确；开关未开是否是根因目前未经证实（见第 0 节），不要预设就是这个原因；确认要开开关就加 `--enable-draft-switch`（不可逆） |
| 提交发布（`--submit`）报 `48001 api unauthorized` | 这一步的原因已核实：账号大概率不是企业主体已认证账号，`freepublish_submit` 只对企业认证账号开放；草稿已建好，去后台手动发布，或升级认证后再用 `--submit` |
| 任意接口报 `43002 require POST method` | 检查请求方式是不是写成了 GET——`draft/switch` 等接口官方文档已明确要求 POST（2026-07 复核修正：此前"文档标 GET"的说法不准确，已在 `wechat-official-api-guide.md` 更正） |
| 发布状态一直是"发布中" | 属于正常异步等待，`wechat_official_publish.py` 会自动轮询；超时了用 `--check-publish-id` 单独查一次，不代表失败 |

排查思路走不通时，回到 [references/wechat-official-api-guide.md](wechat-official-api-guide.md)，或让 Claude 直接跑 `--check-draft-switch`/`--check-publish-id` 帮你读结果。
