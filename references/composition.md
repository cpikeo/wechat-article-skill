# 构图与节奏

`SKILL.md` 说"构图先于装饰"，本文件说怎么做。这里不提供模板，只提供量尺与判断顺序：先把物理条件量清楚，再谈比例、重心与节奏。

## 0. 先量版心

手机单栏的物理约束是硬的，所有构图决定都在它里面发生：

| 项 | 实际范围 | 意味着 |
|---|---|---|
| 屏宽 | 320 / 360 / 375 / 390 / 430px | 同一份版面要在五个宽度上成立，为 390 调的间距在 320 上不能挤死 |
| 正文 | 15.5–16.5px | 再小就把"克制"做成了"费眼" |
| 页边 | 10–24px（可左右不等） | 页边是版心的成本：24px 的页边在 320 上只剩 272px |
| 行宽 | 320 上约 17 字，430 上约 25 字 | 低于 15 字，眼睛每行都要做一次大返程，版面碎成条 |
| 行高 | 1.74–1.96 | 与字号成反比：字越小、行距越大；`frost` 15.5px 配 1.74，`letter` 16px 配 1.96 |

**先算，再设计。** 想在 320px 上放一个 26px 的标题加一个悬边编号，就要先算出标题还剩多少字宽：284px ÷ 26px ≈ 10 字。算不出来就不要写"字号再大一点"这种话——那是把审美判断留给运气。

## 1. 比例与张力

单栏版面里，"张力"来自三件事，其它都是派生：

**不对称的页边。** 左右等宽是默认值，不是决定。`letter` 用订口 28 / 切口 16：读者读到的第一行从偏右的位置起笔，整页因此有一点"往切口走"的动势。做不对称的前提是**版心宽度按两边的平均值记账**（`margin`），否则表格与分栏会算错可用宽度。

**参差的右端。** 强行两端对齐在中文单栏里会把字距撑开、把标点挤扁，读者看到的是"被拉过的行"。左对齐 + 参差右端是正解；参差本身就是节奏。

**收进的栏宽。** 全篇同宽的段落是平的。让两类文字收进：导语右端收 8–12%，引语整段退一栏。收进不要超过 15%——超过就成了"引用块"，读者会以为那段话不是本文写的。

**不要居中。** 居中是版面的最后手段：它把左轴交出去，换来的只有对称。一页最多一处居中（通常是结尾的一句）。

## 2. 视觉重心

一页只该有一个重心。判断方法：眯眼看这一屏，最先落到哪里？

- 重心由**尺寸阶跃**（字号差 ≥5px）、**明度对比**（一段深色或一大块底色）、**留白围合**三者之一建立，三者同时用会打架。
- 重心位置不要总在同一处。全篇每屏都在同样的位置出现重元素，读者会把它读成模板。
- **留白要围着重心造**：重心周围的空要明显大于别处，读者才知道往哪看。平均分配的空不是留白，是没排版。

## 3. 节奏：四种间距，四级气口

距离就是关系。同一份版面里，间距只有四档，档与档之间必须能看出差别：

| 档 | 用途 | 相对量级 |
|---|---|---|
| 部次 | 换章、换场景 | 最大，且开篇一章大于后续章 |
| 段落 | 同一思路的推进 | 跟行距走（约行高的 0.5–0.7），不跟版式网格走 |
| 块 | 图、表、数据、代码与正文之间 | 与部次接近但小一档 |
| 行内 | 标签与数值、图与图注 | 最小，通常 6–14px |

**短章收近，长章放开。** 两段就翻过去的一节是停顿，不是部次；给它部次的气口，读者会以为换了大章。

**节内不许出现等距。** 一段里每两段之间都是同一个间距、每张图上下都是同一个间距，读起来是表格不是文章。至少让进入图表前的气口大于段落间距，退出时略小——读者因此知道"这一段说完了"。

## 4. 图片在动线里的位置

图片不是插图，是动线里的**换气点**。位置决定它承担什么：

| 位置 | 任务 | 构图要求 |
|---|---|---|
| 首图（标题之后） | 定场景、给读者一个具体的房间 | 具体主体、有前景；不与封面重复同一构图 |
| 章首图 | 换场 | 与上一张换景别或换机位，不换光源 |
| 中段图 | 打断长文、给一次停顿 | 可以更安静，允许大面积留白 |
| 解释图 | 说清机制 | 结构清楚、层级分明、零虚构 |
| 结尾图 | 收束 | 安静、有余韵，不重复开篇构图 |

**尺寸只有三档，且要阶跃着用**：

1. **出血**（反推到屏幕两缘）：全篇 0–2 张。它取消了页边，是全篇最重的一次视觉停顿，只能用在全篇最需要一个"停顿"的地方。用两次以上，读者会以为这是排版风格而不是强调。
2. **版心**（与正文同宽）：默认档。
3. **收进**（内缩 4–12%）：用于细节、材质、次要证据；连续两张收进图会让版面显得怯。

**同一档连用两张就是平。** 判断方法：把这一屏的所有图按宽度排一遍，如果全是同一个宽度，就换一档。景别也要跟着阶跃：远景 → 中景 → 特写，至少两级，最多四级。

**图注属于图，不属于正文。** 图与图注之间的间距必须小于图注与下一段之间的间距，否则图注会被读成上一段的结尾。

## 5. 信息形式的移动端降级

桌面能读的形式，手机上经常读不成。降级不是丑化，是换一种更小的容器：

| 原形式 | 什么时候降 | 降成什么 |
|---|---|---|
| 三列以上的表 | 任一单元格折行后只剩一两个字（孤字行） | 记录卡：首列做标题，其余列成"标签—值"两列 |
| 横条图 | 三四项、标签短（≤6 字） | 竖柱：高低差一眼看得见，基线就是零起点 |
| 竖柱图 | 项数 >4 或标签长 | 横条：标签读得完，值在右侧对齐 |
| 时间线 | 日期列放不下 6 字 | 把日期并进事件句首（"1868 年，……"），退回正文 |
| 缩进引语 | 版心 < 280px | 取消缩进，改用字号与颜色区分 |
| 双栏对照 | 任一栏 < 140px | 上下排列，用一道发丝线分隔，不用"左/右"字样 |

降级判断由渲染器按 320px 执行，编辑看到 `已自动降级` 时不要去"修"渲染器，而应判断：是内容该压短，还是这张表本来就不该存在。

## 6. 自检：打开真机之前

按 390px 从第一屏往下滑一遍，逐项过。任一项答不上来，版面就还没定稿：

- 第一屏有没有一个明确的入口？读者知道自己在读什么、值不值得读下去？
- 眯眼看每一屏：重心在哪里？相邻两屏的重心是不是同一个位置？
- 有没有一屏是纯文字且超过 12 行、中间没有任何换气？
- 图的宽度是不是连着三张都一样？景别有没有变化？
- 章节之间的距离，能不能看出"新的一章"和"一次停顿"的差别？
- 把版面转成灰度：层级还在吗？如果层级靠的是颜色，灰度下就会塌。
- 把字号放大 130%：还有没有孤字行、标题折三行、表格挤爆？
- 复制到微信编辑器之后，负边距的出血图还在不在？（不在，就改成版心图，不要留一张半出血的图）

**浏览器截图只是近似。** 微信客户端会重写字体栈、重算行高、重排图片；`UNVERIFIED` 就是 `UNVERIFIED`，不要用本地截图替代真机验收。
