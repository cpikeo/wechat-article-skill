# 素材工艺（按需读取）

设计判断、资产职能与取舍只见 SKILL.md。本文件不另设美学阈值或固定禁用风格。

## 从 brief 到资产

把用途、主语、构图、镜头、光照、材质、色盘、画幅与移动裁切写进描述；同篇保留关键物理条件的一致性，不要求逐字复制 Prompt。不要靠「masterpiece／4K」代替方向。纪实图不为色盘统一而改事实。

例如解释配电设施：铜排与螺栓近景，平视，柔和顶光，冷灰柜体、低饱和铜色，3:2；若生成，说明「AI 生成示意」，不称为项目实拍或证明技术细节。

**先定性，再选图**：同一张图可能是实拍、资料图（馆藏扫描、档案、截图）、AI 示意或数据证据，四者的读者预期与图注要求完全不同。文件里用职责词写清：`实拍 photo`、`资料 archival`、`证据 evidence`、`数据 data`，AI 生成的再加 `ai`/`generated`。`资料/实拍` 的图注或紧邻来源行必须写明出处与授权（馆藏编号、CC BY/CC0、摄影者、档案号），否则 Gate 2 拦截；`证据/数据` 必须有可核对来源链接，且不能是生成图。

生成或下载后过目主语、错误构造、多余文字、水印、授权与来源。V11 评测图均为程序生成示意，已在图内与图注标明，不作为新闻或效果证据。没有信息增量就删，不为填空反复生成。命名用 `images/fig-busbar.jpg` 这类语义路径；引用职责与说明写入 Markdown。文件名和 alt 只是声明，不能证明图中主体；未实际看图时，主体/景别/安全区写 `UNVERIFIED`。

逐图记录：`职责｜可见主体｜来源/授权｜景别与视角｜邻接解释｜裁切/安全区｜信息增量｜保留或删除`。封面与正文图统一主体、光线、材质和叙事条件；比较图尽量保持同尺度，叙事图按全景、动作、细节、结果等真实关系排序。连续同景别没有新增信息时删图。

## 预览对照流程

1. 打开 `*_预览.html`，依次切换 320 / 360 / 375 / 390 / 430，看标题断行、引文换行、数据是否被拆断、图片比例与章节间距。
2. 切换 iOS 与 Android 字体栈，检查衬线或无衬线在两种栈下的行宽与字重是否仍然成立。
3. 点「复制正文」后粘进本机编辑器，确认粗体、引文、列表与数值原子没有被压平；图片位置以路径占位，须在素材库另传。
4. 与真实公众号草稿并排截图对照。没有真机截图的一律记 `UNVERIFIED`，不得写 PASS。

预览里的微信标题栏与底部操作栏是模拟，只用于核对位次与留白，不证明客户端最终排版。

## 封面与分辨率

首图目标 2.35:1，建议1080×460，900×383作为输入基线。预览提供中央1:1模拟裁切；不同入口与客户端裁切不能只靠本地模拟认证。没有可靠出处的已有封面只能作为练习素材，不当真实记录。

正文建议横图宽1200px、竖图短边800px；最终判断取决于显示宽度与细节。低像素由 Gate 2 提示，不作发布硬阻断，但不把所有小示意图称为「必糊」。大图片压到约1MB内，保持清晰；压缩不是放大低清图的替代品。

可选本机工具（运行时不依赖这些工具）：

```bash
# macOS
sips -Z 1400 images/图.jpg
# 已装 ImageMagick 时
magick images/图.jpg -resize 1400x -quality 82 images/图.jpg
```

**每张图的信息职责**：入口（读者第一眼）/ 解释（把正文讲不清的关系画出来）/ 证据（可核对的记录）/ 对比（同一口径的两项）/ 结构（部件与层级）/ 场景（人物与环境）/ 叙事（推进时间、动作或转折）/ 停顿（长文的呼吸）/ 隐喻。说不出属于哪一种、说不出它比正文多给了什么，就删。证据与解释类图片必须紧邻它的解释文字；连续三张同版式的图会变成机械重复，需要换景别或删。

看预览中的图片本身与正文上下文，避免只看资产表。确认图注、字迹、小屏缩放、两种封面裁切；修改回源 Markdown。最终素材完整交付，预览嵌图只为便于查看，不替代正文上传。
