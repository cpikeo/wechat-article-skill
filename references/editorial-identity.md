# Editorial Identity（编辑视觉身份）参考

这份文档吸收了一种更高阶的主题设计思路：**不要把主题设计成"配色方案"，而要设计成"阅读人格"**——一种颜色搭配 = 一种阅读情绪 = 一种品牌人格，而不是"换一种绿色、加一点阴影"式的表面差异化。以下内容基于这个思路整理，但凡是排版尺寸类的具体数值，都根据本组件库已经在 WeChat 环境里实测过的约束做了改编，不盲目照搬——原因见「一、和现有排版数值的差异说明」。

## 一、和现有排版数值的差异说明（必读，避免踩坑）

外部资料里给出的正文字号建议是 **18.5px / 行高 2.0~2.1**，但本组件库唯一的内置主题「静纸」（以及此前已下线的历代主题）经过 WeChat 实测，**正文字号统一锁定 15px，行高最高到 1.9**。这不是保守，是因为：

- 微信公众号编辑器在移动端渲染时，正文字号超过 16px 会显著挤压单屏可读行数，配合大留白反而容易显得"字大留白也大、内容却读得慢"，实际阅读体验和桌面端/独立网站的编辑设计不是同一套物理约束。
- 本组件库的 Gotchas 里已经记录过："不要在同一个 `<p>` 里混多个不同 `font-size`，微信编辑器会自动纠正导致样式被重写"——这意味着字号体系必须谨慎、统一，不能随主题随意加大，`design_quality_check.py` 的字号种类检测也是针对这条踩坑经验设计的。

**结论**：新主题如果想要"呼吸感更强"的编辑气质，优先靠**行高（最高到 2.0）+ 段落间距 + section/图片垂直留白**这三个杠杆去实现，正文字号本身建议保持在 **15~16px** 区间，不建议照搬外部资料的 18.5px。如果用户坚持要更大字号，如实告知这是超出本库已验证范围的改动，需要额外做一轮 WeChat 编辑器实测再确认没有被"纠正"坏。

## 二、可以直接采用的部分：段落呼吸感规则

外部资料"每段 40~70 个汉字，超过就拆"这条经验和本库已有的「无标点文字墙」检测（`design_quality_check.py` 的 220 字硬阈值）方向一致，但更细——它给的是一个"读起来舒服"的软性目标，不是"会不会不合规"的硬红线。**采纳为装配阶段的软性写作指引**：

- 组装正文段落时，优先把一句话控制在 **40~70 个汉字**以内；超过就在语义断点处拆成两个 `<p>`，而不是拆到一半硬切。
- 标题（`##`/`###`）如果转成大号排版元素，控制在 **2 行以内**，按语义断行，不要按字数硬切——例如"如何打造真正具有 / 世界级阅读体验的公众号"这种在语义边界断行，不要"如何打造真正具有世界级 / 阅读体验的公众号"这种在词语中间断。
- 引用（`> 引用`）转换成组件时，优先使用主题库里居中排布的引用组件（多数主题已有），不要用左对齐的大段引用——这是让引用"喘口气"的关键，呼应外部资料"引用单独居中"的建议。
- **英文短语/数字单位不要被中间断行**：正文或标题里出现的英文专有名词组合（如"AI Content Design OS"）、数字+单位（如"16~19 个汉字"里的"16~19"、"v1.0"）如果被公众号自动换行硬生生拆成两半（比如"AI Content" 和 "Design OS" 分两行），会显得很业余。**具体做法**：给这类需要保持完整的英文/数字短语外面套一层 `white-space:nowrap`，阻止内部断行，同时仍要按本 Skill 的合规要求嵌套 `<span leaf="">`——写成 `<span style="white-space:nowrap;"><span leaf="">整个短语</span></span>`，两层缺一不可（外层管断行，内层管样式不被公众号剥掉）。中文字符不受影响，正常按前面几条规则断句断段。只用于**真正会被硬拆、拆了难看**的短语（通常 ≤15 个字符），不要给整段英文都套上，那样反而会在窄屏上溢出。

这几条已经写入 [SKILL.md](../SKILL.md) 第 4 步「生成时的智能处理」，装配时按此执行。

## 三、Section / 图片垂直留白的韵律建议

外部资料给的数值（图片上下 72~88px、section 上下 88px）是桌面端网页的尺度，直接照搬到公众号会显得留白过量、需要多次下滑才能翻过一屏。**改编成移动端安全区间**：

| 元素 | 外部资料原始建议 | 本库改编后建议 | 说明 |
|---|---|---|---|
| 图片上下留白 | 72~80px | **32~40px** | 已经是本库多数主题图片组件的默认间距量级，足够形成呼吸感又不至于让读者觉得"怎么还没到下一段" |
| Section 上下留白 | 88px | **36~48px** | 章节之间的间隔，配合 `design-quality-rubric.md` 的"视觉呼吸感"软指标一起核查 |

新增主题如果想强化"呼吸感极强"的气质（比如下面第四节 Silent Paper 这类），可以在这两个区间的**上限**取值，但不建议超出，避免公众号阅读体验从"从容"变成"拖沓"。

## 五、主题命名方式的建议调整

新增主题登记到 `theme-index.md` 时，除了"中文名 + 英文标识"，鼓励再补一句**阅读人格描述**（一句话说清楚"这套主题的阅读情绪是什么"），而不只是罗列适用场景标签——例如"静纸：安静、克制、长期阅读"就是一句阅读人格描述，比单纯"适合深度文章/生活方式类内容"更能帮用户判断这套主题对不对味。`theme-generator.md` 收集偏好时如果用户描述的就是一种"情绪"而不是"颜色"（比如"我要那种安静克制、读起来不累"的感觉），直接对照本文档第四节找最匹配的阅读人格，而不是逐个追问色值。

## 六、中文断行细节（Optical 层面的真实改进，已落地）

除了上面几节的宏观建议，还有一处纯技术性但确实影响观感的细节：**标点避头尾**（中文排版规则，标点符号不应该出现在行首，比如"。"、"，"落到下一行开头会显得很业余）。这不需要 AI 手动去算每一行在哪里断——CSS 有一个原生属性 `line-break: strict` 就是干这个的，让浏览器/webview 自动应用东亚文字断行规则。

**已经把这条加进本组件库全部 7 套主题的全局容器样式里**（`line-height` 声明后追加 `line-break:strict;`），不需要用户或 Claude 每次手动处理。这是一处真实、低风险、可验证的排版改进，不是纸面建议——已重新跑过全部主题的合规校验，0 ERROR。

**已知限制**：这个属性在现代移动端 WebView（iOS Safari / 微信内置浏览器普遍基于较新内核）里支持良好，但本 Skill 用于自检的 `wkhtmltoimage` 渲染工具内核较旧，可能无法在本地预览中体现效果——如果需要肉眼确认实际效果，以真实发到公众号预览为准，不要只看本地渲染图。

## 七、可行性核查：外部资料里的"高级视觉大气层"在公众号平台的真实落地情况

又一轮外部资料建议加入雾化层（Fog）、噪点/胶片颗粒（Noise/Film Grain）、纸张纹理（Paper Texture）、毛玻璃（Glass Mist）、超弱杂志网格（Grid Layer）、基线网格（Baseline Grid）等"氛围感"手法，来源多是桌面端网页设计（Apple 官网、独立杂志官网）的做法。**逐条核查是否能在本 Skill 的公众号 HTML 约束下真实落地**，而不是照单全收——这是本组件库一贯的做法（同类核查见本文档「一、和现有排版数值的差异说明」）。

| 手法 | 能否落地 | 原因 |
|---|---|---|
| Fog Layer（雾化背景） | ❌ 不能 | 常见实现是半透明色块 + `blur()` 叠在内容后方，需要 `position:absolute` 定位背景层——SKILL.md「平台红线」明确禁止 `position:fixed/absolute/sticky`，没有定位就无法叠层，不是"效果弱"的问题，是根本做不到分层 |
| Noise Layer / Film Grain（噪点颗粒） | ❌ 不能 | 唯一能落地的做法是铺一张噪点贴图做 `background-image`，但公众号正文图片必须是"本地下载→替换成微信域名"的真实素材图（见 `visual-assets-guide.md`），不是外链纹理图；且背景图叠加同样需要定位或 `background-blend-mode`，不在「可用」的样式白名单里 |
| Paper Texture（纸张纹理） | ❌ 不能 | 同 Noise Layer，需要背景纹理图 + 极低透明度叠加，公众号正文没有"背景图层"这个概念（`<section>` 的 `background` 只能是纯色/`linear-gradient`，不能叠两层） |
| Glass Mist（毛玻璃） | ❌ 不能 | 依赖 `backdrop-filter: blur()`，不在「平台红线」的可用样式清单里，未经验证的属性一律当作会被公众号编辑器粘贴清洗掉处理，不承诺支持 |
| Grid Layer（超弱杂志网格线） | ❌ 不能 | 需要背景网格图或 `display:grid`，后者已被平台红线明确禁止；伪装成极细分割线阵列的话，观感和"网格"完全是两回事，不算真正落地这个手法 |
| Baseline Grid（基线网格对齐） | ⚠️ 精神上可以，字面上不行 | 没有 CSS Grid、没有絶对定位，做不到严格的像素级基线对齐；但**效果的核心诉求**（全篇文字节奏统一、不会看起来忽大忽小）已经靠「字号阶梯只开 4~6 级 + 各字号固定搭配唯一行高」的方式实现（见静纸主题设计变量表），这是本库一直在做的事，只是没叫这个名字 |
| Soft Gradient（背景微渐变，如 `#FFFFFF → #FAFAF8`） | ✅ 可以 | `linear-gradient` 在「平台红线」的可用清单里，是唯一能合法叠加视觉层次的背景手法 |
| Ambient Glow（卡片空气感阴影，用极大扩散半径+极低不透明度的 `box-shadow` 代替普通阴影） | ✅ 可以 | `box-shadow` 本身在可用清单里，"空气感"只是把参数调成大扩散、低不透明度（如 `0 20px 60px rgba(0,0,0,.04)`），不需要任何新属性 |

**结论与用法边界**：

- 上面两条✅手法（Soft Gradient / Ambient Glow）**只作为新主题的可选装饰工具**登记进 `design-tokens.md`，不会反向修改静纸（Silent Paper）现有组件——静纸的设计纪律是「没有渐变、没有阴影卡片」（见 `theme-silent-paper.md` 阅读人格描述），这是它"克制"气质的核心，不是尚待补全的缺口，加上去反而破坏这套主题已经验证过的气质。想要更有"空气感"的新主题，走「自定义主题生成」流程重新设计，而不是往静纸里插入。
- 用户如果明确点名要雾化/噪点/毛玻璃/杂志网格线这几种效果，**如实告知在公众号正文里做不到**（原因见上表），可以提供"最接近的可行替代"（微渐变、空气感阴影），不要用近似效果冒充原始需求，也不要在没有测试的情况下声称"应该可以"。

## 八、设计语言（Design Language）分层：从"换主题"升级为"换语言"

外部资料建议把"主题"（Theme，本质是一套配色+组件）升级为"设计语言"（Design Language，一套贯穿色彩、留白、字重、节奏的整体表达）。这个方向是对的、且不需要新代码——本库现有的"阅读人格"命名法（见第四节）已经是设计语言的雏形，这里把它进一步拆成可核对的几个维度，方便设计新主题或诊断"这套主题气质散不散"时使用。

**用序数标签（低/中/高），不用编造的百分比精度**——这是刻意的选择：外部资料给每个主题打"Silence 97 / Weight 82"这类具体数字，这类精度是编出来的（本 Skill 没有能力量化"安静感"到小数点），只会制造虚假的严谨感。序数标签足够指导设计决策，也不假装比实际更精确。

| 维度 | 含义 | 静纸（Silent Paper）示例 |
|---|---|---|
| Silence（留白安静度） | 页面留白 vs 内容密度的比例 | 高——大留白、组件间距宽松 |
| Weight（视觉重量） | 卡片/阴影/色块这类"重"元素的使用密度 | 低——几乎没有卡片和阴影 |
| Breathing（呼吸感） | 段落/章节之间的间隔节奏 | 高——section 间距 40px，图片上下 32px |
| Rhythm（节奏变化） | 组件类型交替的丰富度 vs 单调重复 | 中——组件种类不多，靠留白而非组件切换制造变化 |
| Contrast（对比强度） | 强调色/正文色的对比强度 | 低——全篇仅 1 个强调色，且用量 ≤4 处 |
| Pace（阅读速度感） | 排版是否催促读者快速滑动，还是鼓励停留 | 慢——大留白+短段落鼓励逐句停留 |
| Emotion（情绪基调） | 排版整体传达的情绪 | 沉静、克制 |
| Temperature（色温） | 冷调 vs 暖调 | 中性偏暖（近黑正文 + 鼠尾草绿） |
| Distance（作者与读者的距离感） | 排版是"贴近"读者还是"讲台式"疏离 | 适中偏近——无华丽装饰，像手写笔记 |

**用法**：

- 设计新主题时，先用这 9 个维度写一句话定位（而不是先选颜色），再倒推色板/组件——这是"设计服务于阅读"而不是"设计服务于排版"的具体操作方法，呼应外部资料的核心观点。
- 诊断"这套主题看起来不高级/气质散"时，可以对照这张表逐维度检查：常见问题是 Weight 定位"低"但组件却大量用了卡片+阴影（维度自相矛盾），或者 Rhythm 想要"高"却只有一种组件反复复制——这类问题比"再调一下颜色"更能命中真正的根因。
- 新主题登记到 `theme-index.md` 时，可选附上这张 9 维速查表（不强制），帮助后续维护者快速理解"这套主题为什么长这样"，而不只是留下一堆 hex 值。
