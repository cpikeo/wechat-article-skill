# Format Normalize：输入归一化

排版只认 Markdown。非 Markdown 输入按本文档转成 Markdown 草稿，**转换只整理结构，不增删改写实质内容**。

## 输入类型

| 输入 | 处理 |
|---|---|
| Markdown / `.md` | 直接进流程 |
| `.docx` | `python3 scripts/extract_docx.py 文件.docx -o 文章.md`（零依赖：标题→`#`级、粗体→`**`、下划线→`<u>`、列表→`-`、图片解包到 `images/`、表格转 Markdown 表格） |
| PDF | Read 分页读取：删页眉页脚/页码；行尾无标点且下一行续接→拼成一段；图表位置留 `【配图：原PDF第N页图】`；双栏 PDF 串行错乱则提醒用户 |
| 纯文本 / `.txt` | 标题启发式（短行≤20字+无句末标点+前后空行+序号前缀=`##`；文首孤立短行=`#`）；识别不出则按语义切 3-6 块，自拟章节标题 |
| 网页/富文本 | `<h1-h6>→#`级、`<strong>→**`、`<img>→![]()`、`<li>→- `、`<blockquote>→>`；剥掉样式/`&nbsp;`/剪存元信息块 |
| `.doc`（老格式） | 提示用户另存为 .docx |

## 结构确认（默认必做）

归一化后向用户扫一眼推断结果：
> 识别出 N 个章节：01 xxx / 02 xxx / …（第 X 个标题是我起的）。图片 M 张。结构对吗？

用户说「直接排/一键/不用问」→ 进**全自动模式**：跳过确认，自拟章节标题，交付时附决策说明。
