# 公众号 HTML 的工程边界

SKILL.md 决定设计；check.py 是本 Skill 保守的输入约束，不是微信全部支持能力的证明。

正文门禁采用封闭 allowlist：仅允许 `a/br/img/p/section/span/strong/table/tr/th/td` 与渲染器所需属性；链接仅 HTTP(S)，图片仅相对本地路径且须有非空 alt。内联 CSS 同时校验属性名和值，拒绝未知声明、重复声明、URL/脚本、变量、定位、grid、事件属性、`class/id` 与异常嵌套；字号小于 12px 不通过。代码段落以 `p/span` 输出，CSS 字面量不会被当作样式；`white-space:pre-wrap` 保留代码空格并允许折行。该 allowlist 是本 Skill 当前渲染契约，不等于微信全部支持能力的证明。

窄屏放不下的表格改为「记录卡」：用 section + p 的内联样式排成字段对，不依赖表格布局，清洗后仍保留全部文字与顺序。
有限 flex、语义表格、细线与代码 pre-wrap 是当前保守执行方式；微信编辑器与客户端清洗可能改变它们。V7 检查文字与底色对比、首屏结构、数值原子拆行、导语/章节标题层级与章节标记复读，并在 320/360/390/430px 做浏览器验证。浏览器通过、复制成功、上传成功都不证明真机排版一致。预览标题为平台原生字段的浏览器模拟，不能证明微信客户端标题断行一致。

预览不是发布正文：工具栏、资产表、封面裁切、模拟标题作者与首屏线不复制。预览嵌图片便于独立查看；复制仍指向本地素材，手动编辑器须上传替换。API 上传后才替换为微信图片 URL。来源默认短写「主体＋日期」；确要读者点开的地址单独一行可见输出，是否可点击取决于平台权限。

真实验收要在目标公众号检查：粘贴／API 草稿后正文顺序与字段，保存再打开的样式与图片，手机预览的长表／代码／裁切。没有登录环境时如实列为未验证，不写「PASS 必定兼容」。

## 三级验收不可互相替代

| 级别 | 能证明 | 不能证明 |
|---|---|---|
| 浏览器 PASS | 本地四宽度下的几何、字号、溢出、数值不拆行 | 微信清洗后的样式、真机字体、客户端裁切 |
| API 回读 PASS | 草稿字段（title/content/thumb_media_id）与本地逐字一致 | 后台编辑器重开后的样式、手机端阅读 |
| 微信真机 PASS | 客户端实际渲染、保存重开、iOS/Android、封面两种裁切 | 长期稳定性、不同账号权限差异 |

`render.py --deliver` 生成的 `验收.md` 默认把三者都写成 `UNVERIFIED`，并列出各自需要什么证据才成立；脚本本身不会把任何一级改成 PASS。
