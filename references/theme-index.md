# 主题索引

本 Skill 目前保留**三套内置主题**：静纸（Silent Paper）、暖信笺（Warm Letter）、酌墨（Wine Ink）。此前 7 套主题（摸鱼绿/红白色系/石墨极简风/留白禅意风/摸鱼票据风/橄榄手记/沙丘橄榄）已全部下线并删除——它们要么是色块堆砌、要么是对已有骨架机械换色，达不到"高级简约、有设计感"的要求，与其留着凑数不如删掉。暖信笺、酌墨都不是同样问题的重演：暖信笺围绕"温暖叙事"从零设计（结构骨架、字号阶梯、圆角/阴影使用纪律都单独定义）；酌墨围绕"文人刊物感"从零设计（衬线/无衬线双字体对比、图章式圆环图标系统），都不是静纸换色。

设计来源：静纸色板取自 [editorial-identity.md](editorial-identity.md)「Silent Paper」条目；暖信笺色板为独立新设计；酌墨色板同样独立新设计，未复用现有 Design Token 预设。三套主题的排版尺寸都参考了 `editorial-identity.md`「WeChat 安全改编」版本的字号/留白节奏原则，但具体数值各自独立设定，不共享同一套变量。完整设计说明、组件、Gotchas 见各主题库文件本身。

**深色导语封面区块（可选，2026-07 新增）**：三套主题现在都各自登记了一个"深色导语封面区块"变体（静纸组件 15、暖信笺组件 22、酌墨组件 15），提炼自参考图（Monocle 风格）的"小标签 + 大标题 + 底部短句"结构，深色底按各自主题的色温分别做了区分（静纸中性灰黑、暖信笺暖棕、酌墨暖近黑+衬线标题），**默认都不用**，只在深度报道/年度总结/专栏合集这类需要"郑重开场"的文章类型才考虑换用，且只能替代而不是叠加各主题的组件 1，具体用法见各主题库文件对应组件的说明。

**酌墨与另外两套的核心差异**：静纸/暖信笺的结尾互动区、分割线等装饰元素用 emoji（👍👀📤、· · ·）；酌墨全部替换成「细描边圆环 + 单色 Unicode 排版符号」的图章式图标系统，理由与具体做法见 `theme-wine-ink.md` 组件 13——这是三套主题里目前唯一验证过的"完全不用 emoji"方案，如果用户明确反感 emoji 图标观感，优先推荐酌墨或按其图标手法改造其它主题。

## 锚点强调色核查方式

三套主题的锚点色都与正文主色色相区分明显，且组件库设计时都刻意把"结构性重复元素"（列表圆点、时间线/竖线、页眉细线、图章圆环描边）改用中性/暖灰色，只把 accent 留给真正稀缺的强调——`design_quality_check.py --accent` 检测在三套主题上都可靠：

```bash
# 静纸
python3 scripts/design_quality_check.py <生成的.html> --accent '#6A7567' --accent-quota 4
# 暖信笺
python3 scripts/design_quality_check.py <生成的.html> --accent '#B8583A' --accent-quota 4
# 酌墨
python3 scripts/design_quality_check.py <生成的.html> --accent '#7A2E2E' --accent-quota 4
```

暖信笺有一个静纸没有的取舍：组件 15（关系数据摘要卡）里的大数字本身就用 accent 色，一次典型用法（3 个数字）就用掉 3 处配额，剩给其他组件（金句卡/关键词下划线）的空间很少——**这个组件和组件 7 金句卡/大量关键词下划线不建议在同一篇文章里叠加使用**，用了数据摘要卡就克制一点关键词下划线的次数。

酌墨有一条实测踩过的坑：结尾互动区的图章圆环如果每一个都用 accent 色字符，很容易一篇文章就用掉 3 处配额（见 `theme-wine-ink.md` 组件 13 定稿版）——**定稿做法是三个图章里只有"赞同"一个用 accent，其余两个（在看/转发）用次要文字色**，实测下来全篇 accent 能稳定控制在 ≤4 处；文章头部的"酌"字图章角标也改用主标题色（`primary_text`）而不是 accent，因为它是品牌角标而非内容强调点。

## 选择建议

- 三套主题气质完全不同，**排版前先判断内容类型再选主题**，不要默认套用静纸：人物故事/品牌故事/访谈/回忆录/轻松随笔类优先考虑暖信笺；深度分析/观点/教程/案例复盘类用静纸；**深度评论/书评影评/行业观察/年度总结、或用户明确表示不喜欢现有主题的 emoji 图标观感**时优先考虑酌墨。用户没有明确说明想用哪套时，按文章类型自动判断并在交付说明里注明"这次用的是 XX 主题，因为……"，而不是不声不响地选一个。
- 用户如果对三套主题的气质都不满意（比如想要更强烈的色彩、更商业化的营销感），如实告知现有三套主题的设计定位，不适合的话应该走「自定义主题生成」而不是勉强套用。

## 下划线色值的权威性

正文关键词下划线用上表各主题"正文下划线 CSS"列对应的值（静纸用鼠尾草绿细线，暖信笺用赤陶橙细线，酌墨用深绛红细线），不要跨主题混用色值，也不要用粗下划线/背景高亮块等历史上其它主题用过的手法——那类手法已经被证明是"用力过猛"的设计气味。

## 新主题登记流程（用于自定义主题生成）

1. 把主题组件库写入 `references/theme-{英文标识}.md`（格式要求见 SKILL.md「添加新主题的规范」）。
2. 在上表登记一行，补一句"阅读人格"描述，命名思路见 [editorial-identity.md](editorial-identity.md) 第五节。
3. 在「锚点强调色核查方式」补一行，说明新主题的锚点色是否独立于结构色（判断方法参考本文件"静纸"这一条的写法）。
4. 跑 `python3 scripts/component_lint.py .` 确认 0 ERROR，并按 SKILL.md 第 5.5 步的方法**实际拼一篇真实文章、渲染出来看**，不要只凭代码审查就判断"应该好看"——静纸主题本身就是在这样一轮"拼文章→渲染→挑毛病→改组件→再渲染"的循环里做出来的，第一版草稿也有 accent 超配额、字号阶梯不统一等问题，是靠实际渲染检查出来并修正的。

> 用户想要全新风格时，可走 `references/theme-generator.md` 的自定义主题生成流程：按偏好/参考图（或 [design-tokens.md](design-tokens.md)/[editorial-identity.md](editorial-identity.md) 里的预设）生成区块库（预览存 `assets/theme-previews/`），确认后转标准主题库并按上面流程登记；但新主题即便生成出来，**也不会自动替换静纸成为默认主题**，除非用户明确要求切换默认。
