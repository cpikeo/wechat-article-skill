# 图标与图片资源使用规范（WeChat 安全版）

先说结论：你列的图标库和图片库本身都是好东西，但**公众号正文是一段被复制粘贴进微信富文本编辑器的静态 HTML**，不是一个能跑 npm/React/JS 的网页——这意味着列表里一部分资源能直接用，一部分必须换一种方式用，还有一部分完全用不了。本文档把这件事说清楚，避免生成的文章里出现"看起来该有图标，结果粘贴到公众号后图标消失"或者"图片链接过一阵子就失效"这类问题。

## 一、图标：为什么 npm 图标库不能直接用

`lucide-react`、`@phosphor-icons/react`、`@heroicons/react` 这些**都是 React 组件库**，用的时候要 `import` 进一个跑着 React/构建工具的前端项目，最终编译成 `<svg>` 标签配合 JS 渲染。公众号正文没有这个环境——你不可能在微信文章里 `npm install` 一个包，也没有构建步骤把组件编译出来。

即便退一步，只取图标库里的**原始 SVG 代码**直接嵌进正文（不通过 npm，只复制 `<svg>...</svg>` 那段标记），也大概率不保险：微信公众号编辑器的富文本粘贴清洗机制只保留一个很有限的标签白名单（`section/p/span/strong/img` 等，参见本组件库的合规校验规则），`<svg>` 不在其中，历史上大量实测反馈是粘贴后 `<svg>` 会被整段剥掉，图标直接消失且不报错——这是最容易"本地看着挺好、发出去啥都没有"的坑，本组件库现有 7 套主题从一开始就没有用任何图标库或原始 SVG，也是出于这个原因，不是疏漏。

### 本组件库唯一安全的三种"图标"技术（现有主题都在用）

| 技术 | 示例 | 适用场景 |
|---|---|---|
| **Emoji** | 📦 👉 ✦ 🕳 | 需要一个语义明确的小符号时（提示/踩坑/步骤/亮点），跨平台渲染稳定，公众号编辑器不会剥离 |
| **CSS 绘制的几何图形** | `<span style="width:6px;height:6px;background:#059669;border-radius:50%;">` 画一个圆点 | 需要纯装饰性的点/竖线/分割条时，不依赖任何外部资源，样式内联即可 |
| **文字符号 / 数字编号** | `01` `PART` `→` `※` | 需要结构性标记（章节号、步骤号）时，用排版本身的字重/字号/颜色制造层级，不需要额外图标 |

**新主题如果想要"更精致的图标感"，只能在这三种技术内部做文章（比如用渐变色的圆点、更讲究的编号字体排布），不要引入任何图标库或原始 SVG/图片图标**，除非先在真实的微信公众号编辑器里手动测试确认粘贴后能保留（本 Skill 目前没有条件做这个实测，遇到用户坚持要试的情况，如实告知这是未经验证的路径，风险自负）。

### Iconify / Icones / SVG Repo 这类"搜索引擎"呢？

它们是找图标素材的入口，不是能直接用的格式——同样受限于上面"SVG 大概率被剥离"的问题，实际使用方式仍然是被限制在上表三种技术内，不要因为搜索方便就误以为可以直接把搜出来的 SVG 贴进正文。

## 二、图片：为什么不能直接贴 Unsplash/Pexels 链接

Unsplash、Pexels、Pixabay 这些 CC0 图库本身完全没问题（可以商用、免费、审美普遍在线），问题出在**怎么把图片放进公众号文章**：

- **走官方 API 直发时**：`wechat-official-api-guide.md` 已经写明——正文里的外部图片链接（非微信自己的域名）会被草稿接口直接过滤掉，`wechat_official_publish.py` 也因此专门做了"扫描本地图片自动上传替换成微信图片 URL"这一步。**用这些图库的图片，正确流程是先下载到本地，再走脚本自动上传，绝不是把图库的原始 URL 直接写进 `<img src="...">`。**
- **走手动复制粘贴时**：公众号编辑器的粘贴行为对外链图片不算稳定——有的图库会做防盗链（Referer 校验），复制粘贴时图片可能加载不出来；即使当次粘贴成功，图片仍然指向对方服务器，对方哪天换了图片路径、下线服务，文章里的图就没了。**同样应该先下载图片，再用微信编辑器自带的"上传图片"功能插入，而不是保留外链 `<img>` 标签。**

### 正确的图片使用流程

1. 从 Unsplash / Pexels / Pixabay / Reshot / Kaboom Pics 等 CC0 图库挑图、**下载到本地**（这一步人工做，Skill 不代为联网下载版权图片，避免不确定的授权与内容风险）。
2. 交给 Skill 处理时，Read 本地文件路径即可：
   - 手动粘贴流程：图片作为本地资源直接放进 `assets/` 或工作目录，组件库的图片组件（`max-width:100%;height:auto`）引用本地路径，最终由用户在公众号编辑器手动插入图片替换占位（因为纯手动粘贴流程本身也不带图片上传能力，见 `theme-index.md`/组件库里"图片占位"的约定）。
   - 官方 API 直发流程：`wechat_official_publish.py` 会自动扫描 `<img src="本地路径">` 并调用微信官方上传接口换成 `mmbiz.qpic.cn` 域名的 URL，这一步已经内置，不用手动做。
3. **配图风格要和"静纸"的阅读人格匹配**——安静、克制、留白驱动，配图优先选自然光线、留白充分、去人工感的照片（Unsplash 的建筑/自然/材质类目现成很多），避免高饱和度、强对比、密集堆砌元素的图片，那类图片会把静纸好不容易做出来的克制感一下子破坏掉。不要不管主题气质随手配一张不搭调的图，那也是"看起来努力却不高级"的常见原因之一。

### SVG 插图库（unDraw / Storyset / Open Peeps 等）呢？

这些同样是 SVG，遇到和第一节图标一样的问题——不能直接把 SVG 标记嵌进正文。正确用法是：**在对应网站上先导出成 PNG/JPG 位图**（这几个网站基本都支持导出 PNG，且大多支持改配色贴合主题主色），再按上面"图片使用流程"处理成本地文件走手动粘贴或官方 API 直发。不要尝试内嵌 SVG 源码。

## 三、图标/图片质量检查清单（交付前过一遍）

- [ ] 正文里没有任何 `<svg>` 标签、没有指向图标库 CDN 的 `<img>`（比如指向 `unpkg.com`、`jsdelivr.net` 上图标包文件的链接）。
- [ ] 正文里的 `<img>` 全部指向本地文件路径（手动流程）或已知会被官方 API 直发自动换成微信域名（`mmbiz.qpic.cn`），没有裸露的 Unsplash/Pexels 等图库原始 URL。
- [ ] 配图的视觉气质和所选主题的"阅读人格"（见 `editorial-identity.md`）一致，不是随手拿一张不搭调的图凑数。
- [ ] 装饰性"图标"都来自本文档第一节的三种安全技术之一，没有引入未经验证的图标方案。

## 四、如果用户坚持要更丰富的图标/插图效果

如实告知：公众号平台本身的能力边界决定了"丰富图标库"这条路很难走通，可选的折中方案是——

1. 用 unDraw/Storyset 等网站在线换成主题配色后导出 PNG，作为**大尺寸插画图片**使用（走图片流程，不是图标流程），效果上可以起到"品牌插画"的作用，只是不能像图标字体那样在文字行内穿插小图标。
2. 接受本文档第一节的三种安全技术组合出的"极简图标感"，这也是本组件库现有主题一直在用、且已验证微信兼容的路径。

不要为了满足"看起来更丰富"的诉求而牺牲兼容性，粘贴后图标消失比没有图标观感更差。
