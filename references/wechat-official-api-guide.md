# 微信官方发布 API 直发指南（把排版好的 HTML 自动建草稿、发布拿链接）

微信官方的"新增草稿"接口 `content` 字段本来就接受任意合规 HTML，所以本 Skill 排版引擎生成的自定义主题 HTML，可以原样通过官方 API 发布出去，不需要经过任何第三方转换工具。

本指南配套脚本：`assets/automation/wechat_official_publish.py`（纯标准库实现，不需要装任何第三方命令行工具，也不需要额外 `pip install`）。

## 0. 先看清楚这条路径真正的两道门槛（深度核查后修正，比第一版更准确）

第一版文档只提到"`freepublish_submit` 需要企业认证"，深入查证官方文档 + 微信开发者社区真实报错案例后，发现实际上有**两道相互独立的门槛**，缺一不可：

### 门槛一：草稿箱/发布功能的"灰度开关"（和账号认证与否无关，但因果关系强度需要重新评估）

微信官方文档里专门有一个 `draft/switch` 接口，说明写得很直白：

> 由于草稿箱和发布功能仍处于内测阶段，若公众号没有被灰度覆盖，可能无法体验草稿箱和发布功能……当一个公众号选择开启后，该账号在微信公众平台后台的"图文素材库"将升级为"草稿箱"。

也就是说，`draft/add`（新增草稿）这个接口本身，官方"适用范围"表虽然标注"公众号 ✔ 服务号 ✔"（不要求认证），但看起来账号需要先通过这个开关"开通"新版草稿箱功能才能真正调用——这原本被用来解释为什么微信开发者社区里大量个人账号反馈"文档说能用，实测却报 `48001 api unauthorized`"。

> **2026-07 复核提醒（重要，冲淡了上面这条推论的确定性）**：重新查证官方文档同一页面时，发现文档紧接着这句话之后还有一句：**"内测期间，无论开关开启与否，旧版的图文素材 API，以及新版的草稿箱、发布等 API 均可以正常使用"**——这句话和"开关没开会导致 `draft/add` 报 48001"这个推论是直接冲突的。两种可能都存在：① 官方文档这句话本身就没有更新及时，实际行为确实会卡；② 这句话是准确的，`48001` 更可能另有原因（`access_token` 权限范围、IP 白名单、账号类型本身不支持该接口等），开关状态只是恰好同时出现的无关变量。**本 Skill 目前没有办法拿到真实账号去实测验证哪种解释成立**，因此把原来"开关没开→大概率是 48001 的原因"这个近乎确定的因果表述，降级为"其中一个需要排查的可能性，优先级不必高于 access_token/参数/权限范围排查"。用户实际调用时以官方文档当时的最新描述和实际返回的 errcode 为准，不要照搬这里的旧结论。

**这道门槛和企业认证确定是两件独立的事**（这一点两次核查结论一致，没有冲突）：
- 开关开了之后，`draft/add`（建草稿）本身**个人认证/未认证账号也能用**——这条在两次核查里都成立。
- 开关是否会单独导致 `draft/add` 失败——如上，这条现在只作为**待验证的可能性**保留，不再作为确定结论使用。

### 门槛二：`freepublish_submit` 真发布（这道才和企业认证挂钩）

官方"发布能力"这一组接口（`freepublish/submit`、`freepublish/get` 等，**不包含 `draft/add`**）明确写着：

> 2025年7月起，个人主体账号、企业主体未认证账号及不支持认证的账号将被回收以上接口的调用权限。

这道门槛只卡"真正发布出去、生成正式链接"这一步，不卡"建草稿"这一步。

### 两道门槛合起来看，account 覆盖情况实际是这样：

| 账号情况 | 门槛一（灰度开关，因果强度见上方 2026-07 复核提醒） | 门槛二（企业认证，已核实） | 实际能做到什么 |
|---|---|---|---|
| 个人认证/未认证，开关未开 | ❌ 未过（是否会导致 48001 待验证） | ❌ 未过 | 如果开关确实是原因，`draft/add` 会先报 48001；如果不是，48001 更可能来自权限/参数问题——两种都先按第 3 节 errcode 排查表处理，不要预设是哪一种 |
| 个人认证/未认证，开关已开 | ✅ 已过 | ❌ 未过 | 能自动建草稿（排版引擎产出的 HTML 能用上），发布这一步仍报 48001，需要人工去后台点发布 |
| 企业主体已认证，开关未开 | ❌ 未过 | ✅ 已过 | 先开开关，之后两步都能走通 |
| 企业主体已认证，开关已开 | ✅ 已过 | ✅ 已过 | 端到端全自动：建草稿 + 自动发布 + 拿到正式文章链接 |

**关于"个人/未认证账号只能停在建草稿"这个此前的表述**：企业认证这道门槛（门槛二）是确定的，个人/未认证账号止步于建草稿这一点不受影响；但"开关没开会连建草稿都走不通"这条因果关系目前只是待验证的假设（见上方 2026-07 复核提醒），**遇到 `48001` 时不要预设是哪一道门槛没过**，按第 3 节 errcode 排查表逐项排除，两道门槛都只是候选原因之一，不是唯一解释。

### 怎么检测自己的账号处在哪种情况

```bash
# 只查开关状态，不做任何修改
python3 assets/automation/wechat_official_publish.py \
  --appid "你的AppID" --secret "你的AppSecret" --check-draft-switch
```

返回 `is_open: false` 说明开关没开，`create_draft`/`--submit` 大概率都会先卡在这一步——**和企业认证无关**。确认要开启的话（**这个操作不可逆**，会把公众号后台的"图文素材库"永久升级成"草稿箱"，回不去旧版），显式加参数：

```bash
python3 assets/automation/wechat_official_publish.py \
  --appid "你的AppID" --secret "你的AppSecret" \
  --html "文章.html" --cover "cover.jpg" --title "标题" \
  --enable-draft-switch
```

开关开了之后，再按account是否企业认证决定要不要加 `--submit`。

## 1. 账号资质速查表（结合上面两道门槛）

| 接口 | 作用 | 账号要求 |
|------|------|---------|
| `draft/switch`（查/开草稿箱开关） | 查询或开启新版草稿箱/发布功能 | 公众号、服务号都可以调用，**和是否企业认证无关**；查询（`checkonly=1`）随时可做，开启操作不可逆。**2026-07 复核修正**：官方文档明确标注这个接口的请求方式是 **POST**（`https://api.weixin.qq.com/cgi-bin/draft/switch?access_token=ACCESS_TOKEN`，`checkonly=1` 时同样用 POST），脚本按 POST 调用是对的；此前文档里"官方标注 GET、实测报 43002 才改成 POST"这句话经复核站不住脚，已删除这个不准确的因果描述，只保留"用 POST 调用"这个结论 |
| `draft/add`（新增草稿） | 把 HTML 内容存进草稿箱，拿到 `media_id` | 官方文档标注公众号/服务号都可调用（不要求认证）；**是否一定要先打开上面的开关才能调用，目前没有确凿证据**（见第 0 节 2026-07 复核提醒）——遇到 `48001` 时把开关状态当作待排查项之一，不要预设结论 |
| `freepublish/submit`（发布草稿） | 把草稿真正发布出去，会生成正式文章链接 | 开关已打开的前提下，**仅企业主体已认证账号**可调用（服务号，或已完成企业认证的订阅号）；**个人认证/未认证账号调用会报 `48001 api unauthorized`**（2025 年 7 月起生效的官方限制） |
| `freepublish/get`（发布状态查询） | 轮询发布任务是否成功，拿到 `article_url` | 同上，仅企业认证账号 |

也就是说：
- **开关没开**：不管账号有没有企业认证，`draft/add` 可能都调不通，这条路径对这个账号暂时走不通，只能回退到手动粘贴（或先按第 0 节的步骤把开关打开）。
- **开关开了 + 个人认证/未认证账号**：这条路径能帮你做到"把排版引擎产出的自定义 HTML 自动存进草稿箱"，但**发布这一步仍然要你自己去后台手动点**——这是微信官方对"发布能力"这一组接口的资质限制，不是脚本功能不全。
- **开关开了 + 企业主体已认证**：这条路径可以做到真正的端到端自动化：AI 排版 → 建草稿 → 提交发布 → 轮询状态 → 拿到文章正式链接，中间不需要人工点一下鼠标。

**不确定自己账号是什么情况？** 先跑 `--check-draft-switch` 看开关状态（见第 0 节）；企业认证与否可以登录微信公众平台后台 → 设置与开发 → 账号详情核实，或者直接试跑一次 `--submit`，如果返回 `48001` 且开关已经确认是开着的，就说明当前账号不满足企业认证这道门槛。

## 2. 用法

```bash
# 第一次用建议先跑这个：只查开关状态，不做任何修改
python3 assets/automation/wechat_official_publish.py \
  --appid "你的AppID" --secret "你的AppSecret" --check-draft-switch

# 只建草稿，不发布（适合先确认草稿效果，或账号还没升级企业认证）
python3 assets/automation/wechat_official_publish.py \
  --appid "你的AppID" --secret "你的AppSecret" \
  --html "文章_排版_静纸(silent-paper).html" \
  --cover "cover.jpg" \
  --title "文章标题" --author "作者名" --digest "一句话摘要"

# 开关没开时，确认要开启（不可逆）再加这个参数
python3 assets/automation/wechat_official_publish.py \
  --appid "你的AppID" --secret "你的AppSecret" \
  --html "文章_排版_静纸(silent-paper).html" \
  --cover "cover.jpg" \
  --title "文章标题" --author "作者名" --digest "一句话摘要" \
  --enable-draft-switch

# 建草稿 + 提交发布 + 自动轮询到成功/失败为止（需要企业认证账号）
python3 assets/automation/wechat_official_publish.py \
  --appid "你的AppID" --secret "你的AppSecret" \
  --html "文章_排版_静纸(silent-paper).html" \
  --cover "cover.jpg" \
  --title "文章标题" --author "作者名" --digest "一句话摘要" \
  --submit

# 之前提交过、想单独查一次发布状态
python3 assets/automation/wechat_official_publish.py \
  --appid "你的AppID" --secret "你的AppSecret" \
  --check-publish-id "100000001"
```

脚本自动处理的细节：
- **每次跑主流程都会先查一次开关状态**（`draft/switch?checkonly=1`），开关没开时会打印警告但仍会继续往下尝试（因为开关状态和 `48001` 的因果关系目前未经证实，见第 0 节），真正报错时会列出几种可能原因（开关未开 / 权限范围 / 企业认证限制）供排查，不会笼统归因于"个人账号不能用"，也不会武断认定是哪一种。
- **正文里的本地图片会被自动上传替换成微信图片 URL**——因为官方接口要求正文图片必须来自"上传图文消息内的图片"接口，外部图片链接会被过滤，脚本会扫描 `<img src="本地路径">` 逐个上传替换，已经是 `http(s)` 链接的不动。
- **封面走"永久素材"接口**，不是临时素材——建草稿的 `thumb_media_id` 必须是永久素材 ID，脚本已经调用了正确的接口，不用自己区分。
- **`access_token` 用官方推荐的"稳定版"获取方式**，避免多个任务并发调用互相顶掉对方 token 的问题。
- **发布是异步的**：`--submit` 提交成功只代表"发布任务已受理"，脚本会自动轮询 `freepublish/get` 直到给出终态（成功/失败）或超时；超时不代表失败，可能任务还在进行，用 `--check-publish-id` 补查。

## 3. 发布状态码速查

| `publish_status` | 含义 |
|---|---|
| 0 | 成功，`article_url` 就是正式文章链接 |
| 1 | 发布中，需要继续等 |
| 2 | 原创审核失败 |
| 3 | 常规失败 |
| 4 | 平台审核不通过 |
| 5 | 成功后用户自己删除了所有文章 |
| 6 | 成功后系统封禁了所有文章 |

2/3/4 都属于内容或账号层面的问题，脚本报出状态文字后需要人工去公众平台后台看具体原因，不是重跑脚本能解决的。

### 常见 errcode 排查（不是 publish_status，是接口调用本身报错）

| errcode | 含义 | 排查方向 |
|---|---|---|
| `43002` | require POST method | `draft/switch` 等接口官方文档已明确要求 POST，不是"文档标 GET、实测才发现要 POST"（这个说法经 2026-07 复核站不住脚，见第 0/1 节），如果自己扩展调用了其它接口报这个错，检查请求方式是不是不小心写成了 GET |
| `48001` | api unauthorized | 不要直接归因于"账号没认证"——企业认证限制（门槛二）已核实成立；"草稿箱开关没开"是否也会导致这个码目前**未经证实**（见第 0 节），两者都先列为排查方向，不预设哪个是真正原因 |
| `40001`/`40014` | access_token 无效/过期 | 用 `get_stable_access_token` 的稳定版凭据，检查 `appid`/`secret` 是否正确、有没有多进程互相顶掉普通版 token |
| `45004` | 参数长度超限 | 建草稿时优先检查 `title`/`author`/`digest` 是否超出 32/16/128 字限制，不要先怀疑正文内容 |

微信官方接口的具体行为、权限门槛会随平台策略调整（本文件 2026-07 就复核出一处此前记录不准确的地方，见第 0/1 节），遇到调用报错时，**优先信实际返回的 errcode 和当时最新的官方文档，按 errcode 排查，不要死磕本文件里某条历史结论**。

## 4. 安全与限流提醒

- `AppSecret` 通过命令行参数传入容易被 `ps`/shell 历史记录看到，更安全的做法是用环境变量读取后再传给脚本（脚本本身不做环境变量读取，是为了保持参数来源透明，你可以在调用处自己 `--secret "$WECHAT_SECRET"`）。
- **`--enable-draft-switch` 是不可逆操作**：一旦开启，公众号后台的"图文素材库"会永久升级成"草稿箱"，没有官方接口能切回旧版。第一次使用建议先只跑 `--check-draft-switch` 确认现状，需要开启时清楚这是个单向决定再执行。
- 官方对接口调用次数、`freepublish_submit` 的发布频率都有平台层面的限额，脚本不做任何限流层面的规避，触发限额时如实按官方错误码报出，不重试到"看起来成功"为止。
- 这条路径同样只做到"自动发布单篇文章、生成正式链接"，**不涉及、也不能做"消息推送到粉丝聊天界面"**（那是另一套已经受限的群发消息接口，历史上多数账号类型已不能自由调用）；发布出去的文章会出现在公众号的文章列表里，用户仍需要主动点开或通过其它渠道分享才能看到，这和"主动推送一条消息提醒所有粉丝"是两回事，不要混为一谈。

具体接口字段以官方文档为准，链接见脚本文件头部注释。
